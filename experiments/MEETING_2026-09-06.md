## The one thing the other two need to hear

**Do not plot anything measured inside `game_events_occurred`.**

Measured on our DQN: the online agent logged 45 coins per round while the exact
same weights, saved and reloaded with `train=False`, scored 6.2. A 7x gap. The
weights shift ~100 times per round during training, and that drift was breaking
the action loops a frozen policy falls into. It looked like skill.

The tournament runs a frozen agent. Any learning curve taken from training-time
callbacks describes an agent that will never be submitted. This applies to the
Q-learning arm exactly as much as to ours.

`tools/evaluate.py`, `tools/compare.py` and `tools/confirm.py` all measure
frozen. They work on any agent, not just the DQN. Suggest both arms use them so
the report's numbers are comparable.

## What the DQN work produced

Four bugs, all found by measurement rather than guesswork. Each is report material.

1. **Exploration suicide.** With BOMB in the random action set the agent killed
   itself within a few steps and `--train` ended the round before anything could
   be learned. Fixed by masking BOMB for task 1, which the spec's own task
   description allows.

2. **Online vs frozen (above).** Led to building the whole evaluation harness.

3. **Reward shaping paid for idleness.** The discounted potential
   `gamma*Phi(s') - Phi(s)` with `Phi = -0.1*d` leaves a residual of
   `+0.005*d` per step whenever the distance does not change. Shuffling between
   two tiles ten steps from a coin paid +0.065 every two steps forever, and
   collecting a coin went net negative once the next one was 12+ steps away.
   The arithmetic was right; see the reversal below.

4. **Every next_state was its own state.** A caching bug: the cache key was
   `(round, step)`, but `environment.do_step` increments `self.step` once at the
   top, so the state given to `act()` and its successor carry the same step
   number. Measured: 800 transitions, 800 with `next_state == state`, 100%.
   The Bellman target degenerated to `Q(s,a) <- r + gamma*max Q(s,.)`, which can
   only learn immediate rewards. That is why wall avoidance was learned
   perfectly and coin collection was impossible.

Bug 4 invalidated every experiment before it. Six configurations had all landed
in the same 3-5 coin band, which is what pointed at a common cause upstream
rather than at any of the six variables.

## Two conclusions I got wrong, now corrected by data

**The global view beats the egocentric crop.** `global_view` is the only
configuration that improves monotonically (31.7 -> 47.9) and the only one whose
steps fall steadily (394 -> 236). Every egocentric config peaks around round 250
and then decays. The 13x13 crop discards coins outside the window, so late in a
round, when few coins remain and they are far, the agent is blind.

**The "fixed" shaping performs worse than the version I called broken.** Final
scores: `old_shaping` 44.5, fixed-shaping baseline 32.2. The hovering arithmetic
was correct but it was diagnosing a symptom of bug 4. With usable transitions
the agent finds something better than hovering, and the distance-proportional
term gives a stronger long-range pull toward coins.

Both reversals go in the report as-is. They are better material than a clean run.

## Open problem: training destroys good policies

Most configurations peak at round 250 and decay, with invalid actions climbing
from 0 to 40-80 per round:

```
baseline   250: 47.4 (0 invalid)  ->  3000: 32.2 (46 invalid)
batch32    250: 41.0 (0)          ->  3000: 27.6 (54)
```

Peak performance came while epsilon was still 0.84. Textbook DQN divergence.
`global_view` is immune, which is more evidence the crop is the cause.

Interim policy: **keep the best checkpoint, not the last one.**

## Risks to name out loud

- `DQN_VIEW` is currently read from an environment variable. Official games set
  no environment. If a global-view model ships, the default in `callbacks.py`
  must change or the network is built with the wrong shape and cannot load its
  own weights. Same class of bug as absolute paths.
- The `danger` channel has never been exercised: it is all zeros in coin-heaven.
  The bomb-timer indexing must be re-verified before task 2 depends on it.
- Tasks 2 to 4 are untouched on the DQN side. Task 2 (bomb escape) is the
  critical path and the spec says most losses are self-inflicted.
